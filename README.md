# learn-with-me

一个 Claude Code 的 **skill**：把「怎么教一个人」写成可执行的规矩。

写给这样的场景 —— 你有一个长期带着学的学生（或者你自己），你们一起从零学到能交付。
这套规矩管四件事：**怎么讲、怎么练、怎么查、收工怎么记。**

---

## 它不是学习计划

学习计划告诉你要学什么（Python 8 个域、28 个概念）。
这个 skill 管的是**教的人怎么开口** —— 什么时候只讲一个概念、什么时候闭嘴让他自己写、他报"写完了"的时候先干什么。

---

## 这些规矩是怎么来的

**没有一条是设计出来的。** 每一条背后都有一句真实的话：

| 学生说的话 | 长出来的规矩 |
|---|---|
| 「一头雾水」「不知道你在说什么」 | 一次只讲一个概念；先给现象再讲原理 |
| 「我怎么看」×2 | 长篇材料写进文件，聊天只留一句"写到哪了" |
| 「不用实验，你直接讲」 | 他要结论，不要探索任务 |
| 「我感觉我没有什么参与感」 | 项目代码给 TODO 骨架，别代写成品 |
| 「没懂，你为什么今天这么脑残」 | 他贴代码问"讲讲这段"，先把他那个文件跑一遍 |
| 「你不能这样麻烦地告诉我」 | 别为单个知识点另造脚本让他跑 |
| 「这次怎么这么麻烦」 | 要他自己动手时，一轮只给一条命令 |

**规矩越少越会被执行。** 所以这份 skill 只留了三条铁律，其余全部是展开。

---

## 三条铁律

1. **一次只让他看见一个东西** —— 一个概念、一个现象、一个数字。多了等于没给。
2. **现象我自己跑完，把「代码 + 真实输出」一起贴聊天** —— 不另造脚本让他 cd 过去跑。
3. **他报"整完了" —— 先读文件再开口。** 不看那句话本身。

第 3 条是血换的：连着 5 次，学生报"改完了"，文件里一字未动。

---

## 里面还有什么

- **开工前三读** —— 先读台账/进度文档，别默认今天该出题
- **五步流程** —— 讲 · 练 · 查 · 复盘 · **收工三样**（问答总结 + 错法台账 + 更新进度）
- **出题六条** —— 一个主题串 3 个知识点 / 只给验收标准 / 答案放别的目录 / 故意不给 `__main__`
- **交卷前五条自查** —— 能逐条勾的
- **"我反复翻车的地方"** —— 8 条，全是教学方自己犯的
- **明确写了"什么不进 skill"** —— 课次、台账、提交号这类会过时的东西，只写"去读哪个文件"

---

## 怎么用

把 `SKILL.md` 放进 skills 目录：

```
# 只给自己用
~/.claude/skills/learn-with-me/SKILL.md        # Windows: C:\Users\<你>\.claude\skills\
```

或者放进项目的 `.claude/skills/learn-with-me/SKILL.md`（⚠️ 只有从项目根目录启动才会被读到）。

Claude Code 会根据 `description` 里的关键词自动加载它；你也可以直接说「按 learn-with-me 来」。

---

## 一句提醒

这套规矩里有一半是**教学方自己的违约记录**。

如果你抄了这份 skill，最好也留一节记下你自己翻车的样子 —— 规矩对双方都成立，不然它只是一句抱怨。
